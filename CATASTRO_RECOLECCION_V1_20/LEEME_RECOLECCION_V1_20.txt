CATastro – GESTIÓN DE RECORRIDOS | RECOLECCIÓN V1.20

CAMBIOS IMPORTANTES (basados en el flujo de CRC)
1. Se retira el envío por iframe que se quedaba bloqueado en «Sincronizando».
2. Se recupera el patrón de CRC: POST JSON no-cors a Apps Script, con cola persistente y envío por lotes.
3. Apps Script acepta {token, registros:[...]} y procesa cada snapshot actualizando por ID_REGISTRO.
4. Cada cambio de resultado o GPS reemplaza el snapshot anterior del mismo recorrido y programa envío automático.
5. Al recargar, si había un formulario abierto, aparece una pregunta para recuperar el recorrido con su estado guardado.
6. Guardar y Sincronizar limpian el formulario visible, pero conservan registro e historial.
7. Se mantiene el buscador de MGN.
8. Se mantienen las llaves STORE y QUEUE para conservar datos de versiones anteriores.

IMPORTANTE SOBRE EL ESTADO DE ENVÍO
El navegador no permite leer la respuesta de Apps Script usando no-cors. Por eso la interfaz distingue «Enviado a Sheets» de «Pendiente de envío». El estado «Enviado» significa que el navegador despachó el POST; la verificación real se hace revisando la sábana. El backend hace upsert por ID_REGISTRO, así que reintentar no debe duplicar filas.
